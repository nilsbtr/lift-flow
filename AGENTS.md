# AGENTS.md

Lift Flow is a local-only Flutter gym tracker (Android first). See [README.md](README.md) for features and layout.

## Commands

- Codegen after editing `lib/data/database.dart`: `dart run build_runner build` (build_runner 2.16 no longer has `--delete-conflicting-outputs`).
- Validate every change with `flutter analyze` and `flutter test`. Run `flutter build bundle` too: it catches kernel compile errors that analyze/test miss.
- Android package id: `com.nilsbtr.liftflow`. Clear app data with `adb shell pm clear com.nilsbtr.liftflow`. Read startup errors with `adb logcat -d -s flutter:*`.

## Conventions

- Import `package:material_ui/material_ui.dart`, never `package:flutter/material.dart`.
- Relative imports inside `lib/`. Lints are strict (`strict-casts`, `strict-inference`, `strict-raw-types`, `unawaited_futures`, `prefer_final_locals`). Wrap fire-and-forget futures in `unawaited(...)`.
- Keep code terse and match the surrounding style. Add a short comment only when the code can't explain itself.
- User-facing copy is English, sentence case, and short. Use `’` in text and `kMinus`/`kTimes` from `domain/units.dart` for `−`/`×`.

## Architecture

- **Data** (`lib/data/`): drift tables live in `database.dart` (schema v3), enums in `enums.dart` (re-exported). Repositories wrap all queries; UI never touches `AppDatabase` directly.
- **Providers** (`lib/providers.dart`): repo providers, `StreamProvider`s over drift `watch*()`, `settingsProvider` (Notifier), `restTimerProvider`, `liveWorkoutProvider`, `appLockProvider`, `shortcutTemplatesProvider`, `homeWidgetSnapshotProvider`. `databaseProvider` and the `initial*Provider`s are overridden in `main.dart` with values preloaded before `runApp`, so the first frame has no loading state.
- **Workout editing**: `workoutEditorProvider(id)` (`features/workout/workout_controller.dart`) is an `AsyncNotifier` family. Edits update state right away and are written to the DB after a 400 ms debounce, plus a flush on blur, pause, or dispose. Live workouts are kept alive.
- **Finishing**: `WorkoutEditor.finish({endedAt})` ends a live workout at that time (kept between start and now) and names a workout still called `kDefaultWorkoutName` from its muscles. `DraftExercise.completion` is the one completion rule (it returns the result and the set with its hints filled in), and `toggleDone` and `markAllDone()` both call it; sets marked by `markAllDone()` get no `completedAt`, so they stay out of the timeline and the "last set" time. The finish dialogs live in `finish_dialogs.dart`.
- **Domain** (`lib/domain/`): pure functions, which are what the unit tests cover. `units.dart` handles kg↔lb, parsing, and formatting. `records.dart` handles volume, Epley e1RM, and PRs. `stats.dart` handles weeks, trends, and muscle balance. `muscles.dart` remaps legacy muscle groups. `rest.dart` has the rest adjustments, presets, and time parsing. `finish.dart` has the stale-set and forgotten-workout rules. `workout_name.dart` suggests a workout name.
- **Routing** (`router.dart`): tabs are `/`, `/history`, `/progress`, `/gym`, `/settings`. Full-screen routes (`/workout`, `…/edit`, `/gym/template/:templateId`) use `parentNavigatorKey: rootNavigatorKey`. Detail screens are nested in every tab that links to them (`_exerciseRoute`, `_workoutRoute`), so navigation never jumps tabs. Workout detail lives at `/workouts/:id` (Home), `/history/:id` and `/progress/workout/:id`. Exercise and workout pages link to each other, so those routes nest (`/gym/exercise/1/workout/2`) with numbered path parameters and stop after two hops; `ExerciseDetailScreen.canOpenWorkouts` is false where they stop. To show a day’s workouts, use `showWorkoutDaySheet` (`features/history/workout_day_sheet.dart`) with a `workoutPath` into the current tab. Log past workout creates a finished, empty workout (`createPast`) and opens `/history/log/:id`, which drops it if you leave without a logged set; `purgeEmpty` cleans up after a killed app. Link with `go` to a path in the current tab (`WorkoutDetailScreen` builds on `GoRouterState.of(context).matchedLocation`). Use `push` only for full-screen editors that pop back. The Gym segment is in the URL (`/gym?tab=templates`). Back from a tab root goes to Home. Photo routes (`_photosRoute`) are nested in the Progress tab: `/progress/photos`, `…/compare?a=&b=` (declared before `:photoId`), and the viewer `…/:photoId` on the root navigator (open it with `push`).

## Rules and gotchas

- **Units**: always store kg. Convert only at the UI edge with `kgToUnit`/`unitToKg`/`fmtWeight`. Bodyweight loads are signed: `added` ≥ 0, `assisted` ≤ 0, `none` is null.
- **Set types**: `WorkoutSets.setType` (`SetType`) replaced the old warm-up flag. Only `warmup` is left out of totals, facts, and records (`setType.isWarmup`); drop, failure, and AMRAP sets are working sets.
- **Volume**: use `setVolume`/`SetFact.volume`, which apply the exercise's `perSide` (reps ×2) and `perDumbbell` (load ×2) flags. Records and e1RM use the entered load.
- **Time and distance**: `TrackingType.duration` and `distance` record `WorkoutSets.durationSeconds` and `distanceM` (metres), never reps (`TrackingType.hasReps`). They use `LoadMode.none`/`added` only (`LoadMode.forType`). Format with `fmtSet`, `fmtHms`, `fmtDistance`, `fmtPace` and `DistanceUnit.of(unit, mode)`: km or mi without a load, m or yd with one. They have no volume, rep maxes, warm-ups, plates, suggestions or rep targets; use `SetFact.isLogged` instead of checking reps. Pace values are speeds in m/s, so higher is better. `setStopwatchProvider` times one time set in memory and is separate from the rest timer; a command that ends or leaves a workout must cancel it, as `finish` and `discard` do.
- **Muscle groups**: `arms` and `legs` are legacy values kept for old data and backups. Offer `MuscleGroup.selectable` (or `selectableWith` to keep an exercise's current legacy group) in pickers. In balance stats a set counts 1 for the primary group and 0.5 for each of `secondaryMuscles`.
- **Weeks**: start on `AppSettings.firstDayOfWeek`. Pass it to `weekStart`, `weeklyStats`, `weekStreak`, and `DotCalendar`; never assume Monday.
- **Body weight**: `SettingsController.logBodyweight` (backdated, never in the future, or moving an entry with `replacing`) and `deleteBodyweightEntry` keep `AppSettings.bodyweightKg` equal to the latest-dated entry. Always go through them. The 7-day average (`bodyweightAverages`) is over calendar days.
- **Singleton rows** (`AppSettings`, `RestState`): always write with `id: Value(1)`. Leaving the id out creates a new rowid and duplicates the row.
- **Schema changes**: bump `schemaVersion`, add a migration step, and export schemas (`dart run drift_dev make-migrations`, configured in `build.yaml`). Update `BackupService` export/parse and `kBackupVersion` (now 4) when the shape changes; older versions must keep importing with defaults. Device-local settings (`permissionsPrompted`, `lastBackupAt`, `backupSnoozedAt`, `appLock`, `setMenuHintSeen`) are not exported. Import resets them, except `appLock` (the parser leaves it absent so the device keeps its choice; only delete-all resets it) and `lastBackupAt`, which becomes the file’s `exportedAt`. `ProgressPhotos` stays out of backups, and `BackupService.import` and `deleteAll` leave it alone.
- **Backup and reset** (`features/settings/backup_actions.dart`): export with `exportBackup`, which records `lastBackupAt` once the file is saved. Home’s nudge is `backupNudgeDue` (`domain/backup_nudge.dart`): `kBackupNudgeEvery` (10) workouts finished since the later of the last backup and the last dismissal (`backupSnoozedAt`). `BackupService.import` and `deleteAll` throw `BackupBlockedException` while a workout is live; after either, call `resetAppState`, which drops the cached editors, rest timer and notifications, reloads the settings and reschedules the reminders. `exportCsv` (`domain/csv_export.dart`, one row per completed set) is not a backup and leaves `lastBackupAt` alone.
- **Photos** (`lib/features/photos/`): `PhotoRepository` holds the rows, `PhotoStorage` the files in `<support dir>/photos` (a row keeps only the file name), and `PhotoService` keeps both in step, sweeps orphan files, and exports or merges the zip archive (`photos.json` plus `photos/`; merging skips identical bytes). Nothing else touches paths; show images with `PhotoImage`. `image_picker` (`services/photo_picker.dart`) downscales to 1600 px at JPEG 80 and needs no camera permission, only the `IMAGE_CAPTURE` `<queries>` entry. A photo is never dated after now (`redate`, `PhotoService.add`, archive import). Settings’ “Delete all data” calls `photoServiceProvider.deleteAll()` after `BackupService.deleteAll`; a JSON import keeps photos. `res/xml/backup_rules.xml` and `data_extraction_rules.xml` keep the folder out of Android’s cloud backup, whose 25 MB limit would otherwise stop the database from being backed up. Tests override `photoStorageProvider` with a temp directory and `photoPickerProvider` with a fake.
- **Reminders** (`domain/reminders.dart`): `AppSettings.reminderDays` is a bit mask (bit 0 is Monday) and `reminderMinutes` the minutes after midnight. `planReminders` gives each weekday its own weekly notification, ids 101 (Monday) to 107 on the `workout_reminder` channel, at the wall-clock time from `nextReminder`. Change them with `SettingsController.setReminders`; `syncReminders` also runs at startup, on resume and after an import, because a schedule is tied to the time zone it was made in. The boot receiver in the manifest restores them after a restart.
- **App lock** (`AppLockController` in `providers.dart`, `features/lock/lock_gate.dart`, `services/app_lock.dart`): `settingsProvider.appLock` turns it on, and turning it on or off needs a successful `Authenticator` prompt (`authenticatorProvider`; the real one wraps `local_auth` with the phone's own biometrics or screen lock, and the app stores no PIN). The app is locked on a cold start and after `kLockGrace` (5 min) in the background, measured from the first hide with `onHidden`/`onShown`. `AppLockGate` wraps the router in `app.dart`: while locked it keeps the app alive but offstage, unfocused and without tickers or semantics, swallows the back button and shows `LockScreen`, which prompts once when it appears. Run anything that navigates or mutates because of an external trigger (notification tap, shortcut, a future widget) through `appLockProvider.notifier.whenUnlocked(...)`: it runs at once when unlocked and otherwise after the next unlock. Notification actions (Skip, +30 s) never touch the UI and need no unlock. Any new screen is covered automatically; don't build UI outside the gate. `setRecentsHidden` (`MainActivity.kt`) keeps the app out of the recents thumbnail while the lock is on: `setRecentsScreenshotEnabled` on Android 13+, `FLAG_SECURE` (which also blocks screenshots) below. Tests inject a fake `Authenticator` and pass explicit times to `onHidden`/`onShown`.
- **Shortcuts** (`services/shortcuts.dart`, `domain/shortcuts.dart`): the launcher offers up to `kMaxShortcuts` (4) templates, the most recently started first (live workout included), then the rest in template order. `LiftFlowApp` keeps them in sync with templates and workouts and starts one with `startWorkout`, so the live-workout guard applies; a deleted template just opens Home. Shortcut types are `template:<id>`. A launch that creates the activity reaches Dart twice (launch action and new-intent callback), so `ShortcutService` drops a repeat of the same tap within 3 s. The icon is the `ic_shortcut_workout` drawable, kept from shrinking in `res/raw/keep.xml`.
- **Home widget** (`domain/home_widget.dart`, `services/home_widget.dart`, `android/…/WeekWidgetProvider.kt`): Dart never draws the widget. `homeWidgetSnapshotProvider` builds a `HomeWidgetSnapshot` (first day of week, the days of the last `kWidgetDays` with a finished workout as local `yyyy-MM-dd`, the `nextTemplate` id and name, and whether a workout is live), and `LiftFlowApp` pushes its JSON through `HomeWidgetService.sync`, which skips unchanged snapshots. `WeekWidgetProvider` renders the current week from that and today’s date, so it stays right while the app is closed (30 min update period, a midnight alarm, and clock changes). When the snapshot shape changes, update `HomeWidgetSnapshot.encode`, `Snapshot.read` in the provider and the encode test together, and keep the reader lenient: after an app update it still gets the old shape until the app is opened. `nextTemplate` follows the most recently started template within its folder (or the unfoldered ones), wrapping around. Taps launch `MainActivity` with `liftflow://widget/start?template=<id>`, `/start`, `/workout` or `/open`; `parseWidgetUri` reads them and `_onWidgetTap` runs them through `whenUnlocked` and `_startTemplate`/`startWorkout`. Open only brings the app forward. Colors in `res/values*/colors.xml` mirror `Palette`; the widget follows the system theme, not the app’s.
- **Android activity**: `MainActivity` extends `FlutterFragmentActivity` and the `LaunchTheme`/`NormalTheme` parents are AppCompat themes, both required by `local_auth`. Flutter deep linking is off (`flutter_deeplinking_enabled`), or the widget’s launch URI would reach go_router as a route. `onNewIntent` keeps a widget intent for a task whose process was killed, and `onCreate` drops one from a restored or recents-launched activity, so a tap is not replayed.
- **Isolates**: `Isolate.run` closures inside instance methods capture `this` (the DB can't be sent). Use static closure factories, as in `BackupService._encoder`/`_parser`.
- **Notifications** (`services/notifications.dart`): id 1 is the workout notification (channel `workout_ongoing`), 2 the scheduled rest-over alert, 3 the rest countdown (`rest_ongoing`, times out by itself). Skip and +30 s run in `onNotificationAction`, a top-level entry point in a separate isolate that also runs when the app process is dead. It opens its own `AppDatabase` (no providers or app state), updates the `RestState` row with `applyRestAction`, re-posts the notifications, and pings the app isolate through `IsolateNameServer`, which calls `restTimerProvider.notifier.reload()` (also done on resume). Channel settings are fixed once created, so change a channel's behavior with a new id. With `restSound` on, a rest that ends naturally while the app is in the foreground calls `playRestSound`: Android has no other system sound API, so it posts id 4 on its own `rest_sound` channel (a sound, no pop-up) that times out after 4 s. It never plays on Skip, and a hidden app gets the scheduled alert instead.
- **Riverpod 3**: family notifiers get their argument through the constructor. Use `AsyncValue.value` (there is no `valueOrNull`). `KeepAliveLink` comes from `package:flutter_riverpod/misc.dart`.
- **Sheets**: use `showAppSheet` (`widgets/common.dart`). It uses the root navigator and pads for both the keyboard and the gesture bar.
- **Adaptive layout** (`widgets/adaptive.dart`): layout depends only on window width through `WindowSize.of(context)`: a rail replaces the bottom bar from `kMediumWidth` (600), and list tabs show two panes from `kExpandedWidth` (840). The route tree and URLs are the same at every width. Wrap every route body in `ReadableWidth` in `router.dart` (max `kMaxContentWidth`); don’t stretch a screen edge to edge (the photo viewer is the one exception). A list tab’s routes sit in a `ShellRoute` whose builder is `ListDetail(list:, detail: child)`, and its root route is `ListRoot(list:, placeholder: DetailPlaceholder(...))`; pass the same `enabled` to both where a list has no detail (Gym templates). To add a list/detail tab, do the same, pass the selected id from `state.pathParameters` to the list, and mark the row. The list is a different widget instance on each side of the breakpoint, so keep state that must survive a rotation in a provider (as `HistoryScreen` does), not in `State`, and don’t move it with a `GlobalKey`: a focused field moved under a covered page asserts while painting. In the rail layout `AppShell` handles the left, right and bottom insets and shows the live bar under the content.
- **Timers in UI**: use `PeriodicBuilder` with an `anchor`, not a raw `Timer`/`setState`.
- **Templates**: supersets are neighboring template or workout exercises sharing a `supersetGroup`. Use `domain/supersets.dart` (`normalizeGroups`, `toggleLinkWithNext`, `moveGrouped` with `nearest: true`) and `normalizedSupersets` before `TemplateRepository.save`; save itself does not clean up. Folder collapse is stored (`TemplateFolders.isCollapsed`) and shared by Home and Gym. Group templates with `groupTemplates` and reorder within a section with `reorderWithin`. Rep targets are edited in two digit-only fields (`parseRepsFields`). An assisted exercise’s target weight is stored negative.
- **Supersets in workouts**: a superset is a run of neighbouring exercises with the same `supersetGroup`; a value on one exercise links nothing. Use `supersetRun`/`supersetSpans` (`domain/supersets.dart`, which template code shares), never compare group ids across the list. Reorder with `moveGrouped`, link with `linkGroups`, and draw `SupersetLink` between joined cards. Rounds count working sets only (`DraftExercise.roundOf`); focus goes through `nextFocus` and auto rest waits for `roundOpen`.
- **Loads** (`domain/loading.dart`): bar and plates come from `BarSetup.of(settings.barWeightKg, settings.plates, unit)`, stored in kg with defaults per unit. `loadStep` is the smallest increment for an equipment; `DraftExercise.stepKg` carries it and drives suggested increases (`increaseKg`) and `warmups`. Both switch on `TrackingType`, so add a branch for a new type.
- **Hints**: `hintFor` lines up previous sets by kind (`previousFor`), not by index, and flags a suggested increase with `increase`. `timedHintFor` gives the time or distance placeholder; the optional time of a distance set is never hinted, so a pace is never invented. Anything that swaps the exercise (`replaceExercise`) reloads `previous`, `bests` and `stepKg`.
- **Set delete**: delete sets in the workout screen with `removeSetWithUndo` (`set_menu_sheet.dart`). `WorkoutEditor.removeSet` only hides the set; `commitDelete` writes it when the snackbar closes and on finish, discard, pause, and dispose. A new command that ends or leaves the workout must call `commitDelete` first.
- **Set rows**: the header and rows share their column widths through `SetCols.fit`, which lets Previous shrink before the inputs at large text sizes. Add a column there, not as a fixed `SizedBox`. `SetCols.of` takes the exercise and adds the `distance` and `timer` columns for those types. List finished sets with `SetList` (`widgets/set_list.dart`) and label them with `setLabels`/`setTypeColor`.
- **Effort**: `WorkoutSets.rpe` is always RPE. Convert at the UI edge with `fmtEffort`/`fmtEffortLabel`/`parseEffort` and `AppSettings.effortMode`, and show nothing when the mode is off.

## Theme and icons

- Use tokens from `theme/tokens.dart` (`Space`, `Radii`, `Motion.of(context, …)`, `IconSizes`, `kMinTap`), not magic numbers. Semantic colors come from `LiftColors.of(context)`: `done` (green), `rest` (yellow), `record` (violet), `raised`, `muted`. Red is only for danger and errors: use `colorScheme.error`. Everything else comes from `ColorScheme`.
- Material You: with `AppSettings.dynamicColor` on and system colors available (`dynamicSchemesProvider`, preloaded in `main.dart`, Android 12+), the app uses `AppTheme.dynamicTheme`. Surfaces, text and the accent follow the system; done, rest and record keep their hues and are kept legible with `ensureContrast`. Always check new colors in both themes.
- The text theme defines explicit sizes. Use `Theme.of(context).textTheme` styles and don't hard-code font sizes.
- Icons: use `AppIcon(AppIcons.x)`, not `Icon`/`Icons`. To add an icon, put `name.svg` (14×14 viewBox, Streamline Flex from `api.iconify.design/streamline-flex.json`) in `assets/icons/`, then add `static const x = AppIconData('name')` to `AppIcons`. Icons are precached at startup automatically. Don't use icon-font packages (`flexicon` and `phosphor_flutter` are broken here).
- Launcher icon padding is set by `adaptive_icon_foreground_inset` in `pubspec.yaml`. Don't rescale the PNG.

## Tests

`test/app_test.dart` runs against `AppDatabase(NativeDatabase.memory())`. Add tests there for repository, domain, and backup logic when you change it. Stats live in `test/stats_test.dart`; the workout screen, rest bar, rest sound, and finish dialogs in `test/workout_ui_test.dart`; `test/drift/lift_flow/migration_test.dart` covers every schema step, with data for the steps that convert it. Template, folder and superset tests live in `test/templates_test.dart`. Exercise-level workout tools (plates, warm-ups, supersets, hints, replace) are tested in `test/exercise_tools_test.dart`. Backup status, CSV export, import and reset guards, dynamic colors and reminders are tested in `test/settings_data_test.dart`; the app lock in `test/app_lock_test.dart` and launcher shortcuts in `test/shortcuts_test.dart`. Time and distance exercises are tested in `test/timed_distance_test.dart`. The home-screen widget’s rules, snapshot and tap handling are tested in `test/home_widget_test.dart`. Progress photos (domain, storage, service, archive, routes and screens) are tested in `test/photos_test.dart`. The rail, list-detail panes, resizing and wide-screen overflow are tested in `test/tablet_layout_test.dart`; its widget tests use bounded pumps and close the database in `tearDown`, because awaiting `db.close()` inside `testWidgets` hangs.
